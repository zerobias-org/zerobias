ZeroBias artifact map

Every node is an artifact type the platform dataloader can load — an npm package whose package.json declares zerobias.import-artifact: "<type>" (legacy stanza name: auditmation). The type string — not the package name — routes the package to its loader.

How artifacts connect (4 mechanisms)

  • npm dependencies — load ordering: the dataloader walks npm list and loads leaf deps first.
  • UUIDs — stable id: values in YAML referenced across packages (e.g. product → segment ids).
  • codes / dotted identities — human codes (vendorCode) and dotted package codes (nist.800-53.v5.framework).
  • $ref into a dependency — e.g. a module's OpenAPI references its product's catalog.yml#/Product.

Loading mechanics

Type selection

The loader registry (buildLoaderRegistry()) maps the lowercased zerobias.import-artifact value to a loader class. Package-name prefixes (vendor-, module-…) are convention only — never parsed for routing. The zerobias stanza also carries: package (dotted identity), dataloader-version (min loader version), imports[], skip, deprecated, platform-content (min platform schema version), orgId, migrates-from.

Ordering

After npm pack + install, the dataloader runs npm list -a --json --omit dev and walks the tree. Only packages scoped @nfcc, @auditmation, @auditlogic, @zerobias-org, @zerobias-com with a registered import-artifact enter the dependency list. Children are inserted before parents → leaf artifacts load first, the top-level package last. Each dependency loads in its own DB transaction; first failure aborts the run. A bundle artifact is an empty holder whose npm dependencies carry the real artifacts.

Versioning & environments

Resolution uses npm dist-tags per environment (ENV_TYPE; prod → latest); a skip-dataloader dist-tag skips that exact version. Types in the unrevertable set (product, suite, vendor, framework, benchmark, standard, schema, evidencedefinition, query, evidencebot, kb, tag, pipeline) refuse downgrades and retire older equivalents; other types can coexist in multiple versions. Artifact identity = UUIDv5(npm name).

Naming equivalence (auditmation → zerobias rename)

naming.ts treats @auditlogic ↔ @zerobias-org and @auditmation ↔ @zerobias-com as equivalent scopes and substitutes auditmation ↔ zerobias in names/codes for installed-version checks, retirement and dedup. pipeline is the only type that opts out.

Artifact migration

zerobias.migrates-from re-parents a predecessor package's content rows onto the new artifact, writes a MigratedArtifact sentinel blocking future loads of the old name, and enforces manifest-ID parity before and after. Not allowed for vendor / suite / product.

Post-load events

Loaders publish events after commit: base.ResourceLinker (standard / framework / benchmark / crosswalk / workflow / kb-style generic links), base.BenchmarkLoaded, base.ComplianceFeatureRescan, base.SyncBuiltInRoles (rbac / role / sop).

Hidden DB-level couplings (not obvious from manifests)

  • product and segment both write Offering + ComplianceFeatureSupport — a shared support matrix.
  • pipeline writes Cron rows (type collector_bot) into the same table the cron artifact owns, plus shared-boundary BoundaryProduct/Component.
  • rbac, role, sop and workflow all converge on CatalogRole.
  • benchmark test-case subjectTypes[] must equal existing schema Class names.
  • SCF tables (ScfControl/ScfDomain) are written only by complianceforge.scf* framework packages — evidencedefinition and sop link against them.
  • module ↔ oauth meet in OAuthProvider (provider resolved per VSP).
